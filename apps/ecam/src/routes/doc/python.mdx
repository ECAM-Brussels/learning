# Créer des exercices Python

Dans un exercice Python, l'étudiant·e écrit du code directement dans la page,
l'exécute dans son navigateur,
et la plateforme le corrige en vérifiant une liste de tests.

## Un premier exercice

```tsx
import { PythonCode } from '@learning/exercises/python/Code'

;<PythonCode
  id="carre"
  prompt={
    <p>
      Définissez une fonction <code>carre</code> qui renvoie le carré d'un nombre.
    </p>
  }
  initialCode={'def carre(x):\n    '}
  tests={(expect) => ({
    'carre(3) vaut 9': expect.with('carre(3)').toReturn(9),
    'carre(-2) vaut 4': expect.with('carre(-2)').toReturn(4),
    'carre(0.5) vaut 0.25': expect.with('carre(0.5)').toReturn(0.25),
  })}
/>
```

<Demo.Square />

Chaque test a une description, affichée à l'étudiant·e avec une coche ou une croix,
et une vérification écrite avec `expect`.
La réponse est juste quand tous les tests passent.

| Attribut      | Rôle                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------ |
| `prompt`      | L'énoncé                                                                                   |
| `tests`       | Les tests, écrits avec `expect`                                                            |
| `initialCode` | Le code affiché au départ ; `\n` passe à la ligne                                          |
| `math`        | Ajoute NumPy et les nombres duaux, et affiche les graphiques Matplotlib                    |
| `mode`        | `'manual'` n'exécute le code que lorsque l'étudiant·e clique, utile pour les calculs longs |

## Les vérifications

`expect` exécute le code de l'étudiant·e, puis vérifie ce qu'il fait.
Le **résultat** est la valeur de la dernière ligne du code,
comme dans une calculatrice ;
ce qui est **affiché** est ce qu'écrit `print`.
Quand une vérification échoue,
l'étudiant·e voit souvent pourquoi sous son nom,
par exemple `moyenne([5]) renvoie 5, au lieu de 5.0`.

### Les valeurs

| Vérification                                                      | Vrai si…                                                                     |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `expect.toShow(42)`                                               | Le code renvoie ou affiche `42`                                              |
| `expect.with('f(2)').toReturn(4)`                                 | Après le code de l'étudiant·e, `f(2)` vaut `4`                               |
| `expect.toEqual('[1, 2, 3]')`                                     | Le résultat est la liste `[1, 2, 3]`, comparée en Python                     |
| `expect.output().toEqualThatOf('import numpy as np\nnp.sqrt(2)')` | Le résultat, ou ce qui est affiché, est celui du code donné                  |
| `expect.result().toEqualThatOf(code, 1e-6)`                       | Le résultat est celui du code donné, à `1e-6` près                           |
| `expect.result().toBe(0.1 * 0.1, 0)`                              | Le résultat est exactement le nombre que Python calcule pour $0.1 \cdot 0.1$ |
| `expect.stdout().toBe('Bonjour')`                                 | Le code affiche `Bonjour`                                                    |
| `expect.stdout().toMatch(/bonjour/i)`                             | Ce qui est affiché contient « bonjour », en majuscules ou non                |
| `expect.with('racine(-1)').toRaise('ValueError')`                 | `racine(-1)` lève une `ValueError`                                           |
| `expect.not().toError()`                                          | Le code s'exécute sans erreur                                                |

`toShow` et `output()` acceptent la réponse renvoyée comme la réponse affichée,
même après d'autres lignes :
les étudiant·es affichent souvent leur réponse avec `print` au lieu de la donner en dernière ligne.
Préférez-les à `toReturn` et `result()`,
sauf si l'exercice porte justement sur la valeur renvoyée.

`toEqualThatOf` est le plus pratique :
au lieu de calculer la réponse vous-même, écrivez le code qui la calcule.
Les valeurs sont comparées en Python :
une liste et un tableau NumPy de mêmes nombres sont égaux,
l'ordre des clés d'un dictionnaire ne compte pas,
et deux longs tableaux sont comparés en entier.

Les nombres sont comparés à une erreur relative de `1e-9` près, comme le fait `math.isclose` en Python :
`0.1 + 0.2` vaut donc `0.3`.
Une erreur donnée en second argument est absolue,
comme dans `toBe(3.14, 0.01)` ou `toEqualThatOf(code, 1e-6)` ;
une erreur de `0` exige le nombre exact,
par exemple pour montrer que `0.1 * 0.1` ne vaut pas `0.01` en Python.

### Les fonctions

`function` vérifie une fonction que l'étudiant·e définit,
en l'appelant sur plusieurs entrées et en comparant ses réponses à celles de votre modèle :

```tsx
tests={(expect) => ({
  'moyenne est définie': expect.function('moyenne').toExist(),
  'moyenne est correcte': expect.function('moyenne').toBehaveLike(
    'def moyenne(l):\n    return sum(l) / len(l)',
    [[[2, 4, 6]], [[5]], [[-1, 1]]],
  ),
})}
```

Chaque entrée est la liste des arguments d'un appel :
`[[2, 4, 6]]` appelle `moyenne([2, 4, 6])`.
Un appel peut aussi s'écrire en Python, comme `'np.array([3, 4]), 2'`,
par exemple pour des tableaux NumPy.
Si la fonction donne une autre réponse, affiche son résultat au lieu de le renvoyer, ou lève une erreur,
le message dit pour quel appel.
Comme ailleurs, une erreur peut être donnée en dernier argument pour comparer les nombres.

### Le code

| Vérification                            | Vrai si…                                                                |
| --------------------------------------- | ----------------------------------------------------------------------- |
| `expect.code.toCall('np.linalg.solve')` | Le code appelle `np.linalg.solve`, ou `solve` importé de `numpy.linalg` |
| `expect.code.not.toCall('sum')`         | Le code n'appelle pas `sum`                                             |
| `expect.code.toUse('for')`              | Le code contient une boucle `for`, ou une liste en compréhension        |
| `expect.code.toImport('numpy')`         | Le code importe `numpy`                                                 |
| `expect.code.toDefine('carre')`         | Le code définit une fonction ou une variable `carre`                    |
| `expect.code.toMatch(/epsilon/)`        | Le texte du code contient « epsilon »                                   |

Préférez `toCall`, `toUse`, `toImport` et `toDefine` à `toMatch` :
ils lisent la structure du code,
si bien qu'un commentaire ou un texte entre guillemets qui contient le mot ne compte pas.
`toUse` reconnaît `for`, `while`, `if`, `def`, `lambda`, `return`, `import`, `try`, `with` et `class`.
Le texte entre barres obliques, comme `/epsilon/`, est un motif de recherche :
`i` à la fin ignore les majuscules.

### Les entrées

Pour un programme qui lit des entrées avec `input()`,
`withInput` donne les lignes qu'il lira, dans l'ordre :

```tsx
tests={(expect) => ({
  'Bonjour Alice': expect.withInput('Alice').toShow('Bonjour Alice'),
  'Somme de 3 et 4': expect.withInput('3', '4').toShow(7),
})}
```

Comme dans un terminal, `input()` affiche sa question, puis la ligne lue :
vérifiez donc ce qui est affiché avec `toShow`, qui accepte la dernière ligne affichée, ou avec `stdout().toMatch`.
Un programme qui demande plus de lignes que celles données s'arrête avec une erreur `EOFError`.
Dans la page, quand le code de l'étudiant·e appelle `input()`,
un cadre « Entrées du programme » apparaît sous l'éditeur :
il y écrit les lignes que le programme lira.

### La durée

Un code qui tourne plus de 10 secondes est arrêté,
comme une boucle infinie :
l'étudiant·e voit un message, et peut corriger son code.

## Les graphiques

Avec `math`, les vérifications suivantes portent sur les graphiques Matplotlib de l'étudiant·e :

| Vérification                                                 | Vrai si…                                                           |
| ------------------------------------------------------------ | ------------------------------------------------------------------ |
| `expect.matplotlib.plot('np.sin(x)', -3, 3)`                 | Un graphique contient la courbe de $\sin x$ sur $[-3, 3]$          |
| `expect.matplotlib.plot('np.sin(x)', -3, 3, { points: 20 })` | Pareil, avec au moins $20$ points au lieu de $41$                  |
| `expect.matplotlib.scatter([1, 2, 3], [1, 4, 9])`            | Un nuage contient ces points, dans n'importe quel ordre            |
| `expect.matplotlib.xLabel().toMatch(/x/)`                    | L'axe horizontal a un nom qui contient « x »                       |
| `expect.matplotlib.yLabel().toMatch(/y/)`                    | L'axe vertical a un nom qui contient « y »                         |
| `expect.matplotlib.title().toMatch(/sinus/i)`                | Le titre contient « sinus »                                        |
| `expect.matplotlib.legend().toMatch(/sinus/i)`               | La légende contient « sinus »                                      |
| `expect.matplotlib.grid()`                                   | La grille est affichée                                             |
| `expect.matplotlib.lineCount().toBe(3)`                      | Le graphique contient $3$ courbes                                  |
| `expect.matplotlib.sameScale().toBe(true)`                   | Les deux axes ont la même échelle                                  |
| `expect.matplotlib.xScale().toBe('log')`                     | L'axe horizontal est logarithmique, comme avec `plt.xscale("log")` |
| `expect.matplotlib.axesCount().toBe(2)`                      | La figure contient $2$ graphiques, par exemple avec `plt.subplots` |

`plot` cherche la courbe dans tous les graphiques,
ou dans un seul avec `{ axes: 1 }`, en les comptant à partir de $0$.
Ses extrémités doivent être celles données,
et ses valeurs celles de la fonction, écrite en NumPy avec la variable `x`.
Les autres vérifications lisent le premier graphique,
ou un autre si on donne son numéro, comme `xLabel(1)`.

```tsx
<PythonCode
  id="sinus"
  math
  prompt={<p>Tracez le graphe de la fonction sinus sur [-3, 3], et nommez les axes.</p>}
  tests={(expect) => ({
    'La courbe est tracée': expect.matplotlib.plot('np.sin(x)', -3, 3),
    "L'axe x est nommé": expect.matplotlib.xLabel().toMatch(/x/),
    "L'axe y est nommé": expect.matplotlib.yLabel().toMatch(/y/),
  })}
/>
```

## Demander à l'assistant

:::info[Un exemple de demande]
Décrivez ce que le code doit faire,
puis les cas sur lesquels le tester, y compris les cas limites,
et ce que le code ne doit pas utiliser.

> Crée un exercice Python où l'étudiant·e définit une fonction `moyenne(liste)`.
> Teste-la sur [2, 4, 6], sur [5] et sur [-1, 1].
> Vérifie que le code n'utilise ni `statistics` ni `numpy`.

Écrivez ensuite une solution juste, puis une solution fausse,
pour vérifier que les tests font la différence.
:::

:::remark[Les anciens exercices]
Certains anciens exercices utilisent `Matplotlib`, `PythonFunction` ou une liste de tests `{ desc, test, check }`.
Ces formes sont dépréciées :
les nouveaux exercices utilisent `PythonCode` et `expect`.
:::
